# Android 阅读与执行过程

Android 默认使用“雾蓝灰”：页面背景 `#f5f7fa`、顶栏 `#e8eef4`、工具区 `#f0f3f7`、消息气泡 `#dfe8f2`、输入框 `#f9fbfe`、代码区域 `#e7edf4`，浅色强调色为 `#4c6f98`。输入区省去顶部分隔线，执行详情、复制和引用使用中性灰蓝；链接、选中和悬停状态使用强调色。默认浅色，也可选择配套深色或跟随系统；深色下默认强调色自动提亮为 `#8eafd2`，按钮文字保持可读对比度。旧版默认绿色自动迁移为雾蓝灰，其他自定义强调色以及字体、主题等偏好保留；可在“外观与显示”中恢复默认设置。

从 v2.1.16 起，Android 恢复按网关已启用状态显示应用，支持在 Codex 与 DeepSeek Harness 等客户端之间切换。多个客户端启用时显示底部应用切换栏；也可在列表左右滑动，或在“外观与显示”中控制图标、收起切换栏及关闭滑动。仅隐藏图标不关闭接入，不修改客户端登录或任务。Codex 的 APP、CLI、SSH 与 WSL 接入仍沿用原路由。

DeepSeek Harness 需先在电脑完成安装与登录/API 配置，再到网关“客户端与接入”扫描、配置并启用；插件需要更新时按提示处理。更新电脑网关后，在手机退出当前电脑连接并重新进入即可加载恢复的入口，已有 Android 2.1.13–2.1.15 无需为此重装。这里接入 Harness 的原桌面会话，不是将 Codex 会话切换成 DeepSeek 模型；“Harness 官方 Web”是另一个独立转发入口。

从 v2.1.17 起，Codex 列表短暂刷新失败会保留已加载内容并自动重试，已有列表连续失败三次后才显示中文提示；首次打开没有列表、手动刷新失败或权限错误会立即反馈。点击提示可重试；“连接详情”展示最近的接口路径、错误类型/HTTP 状态、耗时、前后台状态和时间。持续提示占据独立空间，不遮挡第一条聊天。成功刷新自动清除，登录失效按原流程重新登录。共享页面来自电脑网关，现有 Android App 无需为此重装。

聊天顶部合并为一行，点击标题查看执行位置和项目；工作台按钮打开原有的文件、Git、终端等选择器。输入区默认单行，长内容自动增高；上方工具栏可横向滑动，保留模型、发送方式、工作模式、Skill、权限、上下文与提醒。附件、引用、错误和审批有内容时仍占用各自必要的空间。宽屏工作台和分屏沿用原布局。

正文不再重复显示 CODEX、模型与推理强度，仍可从输入区模型入口查看和调整。复制、引用、编辑及分支操作直接显示为消息下方的 14 px 小图标，按钮为 32 px 独立点击区域；长按或悬停可查看原始操作名称，读屏保留完整标签。按钮沿用原始点击和能力校验，复制成功后显示对勾反馈。消息、段落与执行详情间距收紧，工具详情仍可展开，异常提示与待审批内容保留。

从 v2.1.18 起，DeepSeek Harness 共用上述紧凑标题栏与输入行；自动会话上下文默认收起，工具与思考按原生轮次分组，显示实时回复、当前动作与原生耗时。工具调用和结果配对，跨页输出保持完整。详情短暂断线保留正文和草稿，持续失败提供重试。插件 revision 8 需要按任务保护流程重启接入后生效，见 [DeepSeek 手机体验](../docs/architecture/deepseek-mobile-experience.md)。

## 字体

在“外观与显示 → 字体与阅读”分别设置正文与代码字体、字号及正文行距。支持系统字体预设，以及导入 TTF、OTF、WOFF、WOFF2；没有额外下载或打包中文字体库。

每种字体最多保存一个文件，单个文件不超过 20 MiB。字体先通过格式及浏览器解析检查，再写入当前 WebView/浏览器的 IndexedDB，刷新后恢复。字体不上传到网关。删除字体或恢复默认设置会清除保存的字体；导入失败会保留先前可用的字体。

存储按网关地址的 origin 隔离。同一电脑改用另一个协议、域名或端口访问，需要重新导入；清除 App/WebView 数据也会删除字体。普通浏览器中的此设置不改变 Android 原生电脑列表等系统页面的字体。

## 执行过程

共享时间线按原生 `turnId` 和原始顺序，把同一轮连续的工具活动与思考摘要汇总为一个默认折叠区域。面向用户的中途进度说明始终直接显示。摘要统计当前已加载的工具活动，不推测读取了多少文件或模块；加载更早内容后，计数随之更新。公开进度、回答、用户干预或任务级错误会分隔过程区域，避免打乱时间顺序。

工具图片、文件变更汇总、任务级错误、待审批和待回答保持独立可见。单次工具异常保留在折叠的执行详情中，摘要显示异常数量；命令的非零退出码保留原值，不直接当成整个任务失败。即使关闭过程显示，也保留异常摘要。展开状态在流式更新、翻页和显隐切换时保留；详细输出仍通过原来的按需读取接口获取。

执行时底部按官方的当前动作规则显示一条摘要，并按原生本轮开始时间显示耗时。有目录的搜索显示“正在搜索 supply_mall_server 文件夹中的文件”，没有目录才显示搜索词；读取显示文件名，列目录显示“正在列出某目录文件夹中的文件”。普通命令和远端 SSH 命令显示实际命令描述，按原生状态显示“正在运行”“已运行”或“已停止”。常见口令、令牌参数在摘要中脱敏。搜索、读取和目录动作采用活动摘要文案，本轮结束后清除。

优先选择仍在执行的原生调用，否则保留最近调用；同一调用包含多个解析动作时，底部显示最近一项，完整动作、搜索词和目录信息继续保留在执行详情。不会按定时器轮播来猜测命令内部进度。长摘要自然换行，避免单行省略隐藏官方描述。待确认请求优先显示；连接断开或切换聊天时清除旧状态并停止计时。收到新事件后立即继续接收下一次更新，不额外固定等待 200 毫秒。

## 验证

```sh
npm ci --ignore-scripts
npm run test:desktop
python3 -B scripts/test-backend.py --source-only -p test_timeline.py
python3 -B scripts/test-backend.py --source-only -p test_web_assets.py
python3 -B scripts/test-backend.py --source-only -p test_resource_layout.py
CMB_FIXTURE_ONLY=1 CMB_ANDROID_UI_FIXTURE=1 node scripts/smoke-wsl-app-ui.cjs
```

最后一条命令打印一个 loopback 地址。浏览器打开后点击“运行界面检查”，执行生产页面、真实 DOM 与 IndexedDB 的合成验证；不要把此检查用于真实网关。分别检查 390×844、844×390 和 1440×900。

UA 模拟和浏览器检查不等于 Android WebView 实机验证。

## 本机测试 APK

准备好项目 `.tmp/mobile-tools` 中的 JDK、Android SDK 和 ZXing 后，运行：

```sh
python3 scripts/build-mobile-android.py --dev-app
```

生成 `dist/mobile-preview/Codex-Mobile-Bridge-2.1.6-Dev-Android.apk`，名称为 Codex Bridge Dev，包名 `io.github.bufferducky.codexbridge.dev`，可与原版共存。Dev 签名保存在 `.local/android-signing/dev-debug.p12`，后续测试版本应继续使用该文件；不要提交或随安装包分发。

共享 Web 页面来自电脑网关。手机安装 Dev APK 后，需要连接运行此分支源码的开发网关，才能看到全部界面改动；连接旧网关仍使用旧页面。配套试用 ZIP 使用独立端口 18789 与独立状态目录，不替换现有桌面 App。

本机构建已通过原生编译、APK 签名、zipalign 和包内容检查，尚未执行 Android 真机安装。
